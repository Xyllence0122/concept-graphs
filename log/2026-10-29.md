### 本次目標

- 先以靜態 RTAB-Map 地圖降低整合難度，完整走通一次接近官方
  ConceptGraphs 的離線資料流程。

  camera intrinsics 與 camera poses。

### 完成內容

#### 1. 重新建立 RTAB-Map 靜態測試地圖

- 產生 RTAB-Map database：`lab_smoke_2026-10-29_01.db`。
- database 大小約 34 MB，保存在本機
  `$HOME/Concept Graph/concept_graph_data/rtabmap/`。

#### 2. RTAB-Map RGB-D 與最佳化相機姿態匯出

- 使用 `rtabmap-export --images --images_id --poses_camera --poses_format 11`
  匯出 keyframe RGB、毫米深度圖、逐幀相機內參與最佳化 camera poses。
- 本次有效且完整配對的 keyframes 共 38 幀。
- 新增 [`../offline_tools/export_rtabmap_dataset.py`](../offline_tools/export_rtabmap_dataset.py)：
  - 強制 RGB、depth、calibration 與 pose 的 RTAB-Map node ID 完全一致；
  - 將深度限制在 5 m，無效深度寫為 0；
  - 產生連續編號的 `rgb/`、`depth/` 與 `poses/`；
  - 由逐幀 calibration 計算中位數相機參數；
  - 產生 `camera_config.yaml` 與包含來源 node ID、timestamp、深度有效率的
    `manifest.json`；
  - 正確處理 upstream `RealsenseDataset` 載入時使用的
    `diag(1,-1,-1,1)` 座標軸轉換。

#### 4. 官方 ConceptGraphs 獨立環境與 GPU 驗證

- 使用獨立 Conda environment `conceptgraphs-official`，與 ROS 2 Python 3.12
  環境隔離。
- 初次 `import torch` 失敗：
  `libtorch_cpu.so: undefined symbol: iJIT_NotifyEvent`。
- 已定位為 PyTorch 2.0.1 搭配過新的 MKL 2025.3.1；同時原環境解析到
  NumPy 2.2.6，也不適合這套舊版 PyTorch/官方依賴。
- 將 MKL、Intel OpenMP 與 NumPy 降至相容版本後，PyTorch import 與 CUDA
  matrix multiplication 均通過。

### 已知限制

- 今日資料只有 38 個小範圍 keyframes，不能代表完整實驗室覆蓋率或
  loop-closure 品質。
- PLY preview 只能驗證 RGB-D、intrinsics 與 pose 的基本幾何一致性，不能取代
  官方 pipeline 的物件分割、CLIP feature、instance association 與 graph
  建構驗證。
- 目前只驗證 PyTorch/CUDA；PyTorch3D、FAISS、Grounding DINO、SAM 與完整
  upstream dependencies 仍需逐項驗證。
- 原始 upstream `environment.yml` 使用 NumPy 1.24.3；本機修復後是 1.24.4。
  兩者同屬 NumPy 1.24 ABI 範圍，但跨裝置部署仍應以完整環境測試結果為準。
